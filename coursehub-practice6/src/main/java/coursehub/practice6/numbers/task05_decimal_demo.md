# Задание 5. `BigDecimal` без сюрприза double

## Условие

Сравните `new BigDecimal(0.1)`, `BigDecimal.valueOf(0.1)` и строковый конструктор. Рассчитайте стоимость трёх курсов и объясните разницу представлений.

## Где код

- `DecimalDemo.java`
- тесты: `DecimalDemoTest.java`

## Три способа создать `0.1`

| Способ | Значение | unscaled | scale |
|---|---|---|---|
| `new BigDecimal(0.1)` | `0.1000000000000000055511151231257827021181583404541015625` | длинное число | 55 |
| `BigDecimal.valueOf(0.1)` | `0.1` | 1 | 1 |
| `new BigDecimal("0.1")` | `0.1` | 1 | 1 |

Объяснение:

- Литерал `0.1` в `double` хранится как ближайшее двоичное число, оно не равно десятичной одной десятой. `new BigDecimal(double)` честно переносит это точное двоичное значение.
- `BigDecimal.valueOf(double)` идёт через `Double.toString`, то есть берёт короткое десятичное представление, поэтому получается `0.1`.
- Конструктор от строки задаёт значение явно и не зависит от двоичной арифметики. Для денег и данных из внешних источников это основной способ.

## Стоимость трёх курсов

Цены 49,90 + 29,90 + 19,90:

| Способ | Итог |
|---|---|
| `double` | `99.69999999999999` |
| `BigDecimal` из строк | `99.70` |
| `BigDecimal.valueOf(double)` | `99.7` |
| `new BigDecimal(double)` | `99.69999999999999573674358543939888477325439453125` |

## Масштаб и сравнение

- Значение `BigDecimal` = `unscaled × 10^(-scale)`. `2.0` и `2.00` — разные представления одного числа (scale 1 и 2).
- `equals` учитывает scale: `new BigDecimal("2.0").equals(new BigDecimal("2.00"))` — `false`.
- `compareTo` сравнивает числовое значение: результат `0`.
- Поэтому для проверки числового равенства нужен `compareTo`, а для денег scale фиксируется на уровне типа (см. `Money`, задание 14).

# Задание 6. Масштаб и округление

## Условие

Распределите скидку между позициями так, чтобы итоговая сумма точно совпала с ожидаемой. Режим округления передаётся явно; остаток копеек распределяется детерминированно.

## Где код

- `DiscountAllocator.java`
- тесты: `DiscountAllocatorTest.java`

## Алгоритм

`allocate(totalDiscount, prices, scale, roundingMode)`:

1. Скидка должна точно представляться в заданном `scale` (иначе `IllegalArgumentException`) и лежать в диапазоне от нуля до суммы цен.
2. Для каждой позиции считается точная доля `скидка × цена / сумма цен` с запасом точности, затем она округляется в `scale` переданным `RoundingMode`.
3. Считается, сколько минимальных единиц (копеек) не хватает или лишнее: `скидка − сумма округлённых долей`.
4. Эти единицы раздаются по одной:
   - если не хватает — позициям с наибольшей потерей при округлении (разность «точная доля − округлённая» по убыванию);
   - если лишнее — позициям с наибольшим завышением (по возрастанию той же разности);
   - при равенстве побеждает меньший индекс.
5. Итог: сумма долей равна скидке до копейки, порядок раздачи не зависит от запуска.

Режим округления не зашит в код: `UNNECESSARY` приводит к `ArithmeticException`, если округление нужно, а остальные режимы работают одинаково корректно за счёт шага 4.

## Пример

Скидка 10,00 на три позиции по 10,00, `HALF_UP`, scale 2:

- точная доля 3,3333…, округлённо 3,33 × 3 = 9,99, не хватает 0,01;
- остатки равны, копейку получает первая позиция: `[3.34, 3.33, 3.33]`;
- цены после скидки: `[6.66, 6.67, 6.67]`, сумма скидок ровно 10,00.

Скидка 1,00 на позиции 1, 2, 4 (`DOWN`): округлённо `[0.14, 0.28, 0.57]`, не хватает 0,01 — достаётся второй позиции (наибольший остаток): `[0.14, 0.29, 0.57]`.

Скидка 10,00 на три по 10,00 с `UP`: сначала `[3.34, 3.34, 3.34]`, лишняя 0,02 снимается с позиций с наибольшим завышением, при равенстве — с первых по индексу: итог `[3.33, 3.33, 3.34]`.

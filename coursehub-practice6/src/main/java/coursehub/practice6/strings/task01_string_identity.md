# Задание 1. `String`: identity и value

## Условие

Предскажите `==` и `equals` для литералов, `new String`, concatenation compile-time/runtime и `intern`. Сформулируйте правило сравнения текста, не опирающееся на pool.

## Где код

- `StringIdentityDemo.java`
- тесты: `StringIdentityDemoTest.java`

## Предсказание и фактический результат

| Выражение | `==` | `equals` | Почему |
|---|---|---|---|
| `"java" == "java"` | true | true | оба литерала — одна запись в string pool |
| `"java" == new String("java")` | false | true | `new` всегда создаёт отдельный объект |
| `"ja" + "va" == "java"` | true | true | константное выражение вычисляется компилятором, получается литерал `"java"` |
| `final String head = "ja"; head + "va" == "java"` | true | true | `final`-переменная с константой — тоже константное выражение |
| `String head = "ja"; head + "va" == "java"` | false | true | `head` не константа, конкатенация выполняется в runtime и создаёт новый объект |
| `(head + "va").intern() == "java"` | true | true | `intern()` возвращает объект из pool |

Фактический вывод `StringIdentityDemo.main` совпадает с таблицей.

## Правило сравнения текста

1. Содержимое строк сравниваем только через `equals` (или `Objects.equals`, если возможен `null`).
2. Для сравнения без учёта регистра используем `equalsIgnoreCase` или заранее нормализованный ключ (см. задание 13).
3. `==` для `String` означает «тот же самый объект», а не «тот же текст». Результат `==` зависит от того, как строка была создана, поэтому на него нельзя опираться в бизнес-логике.
4. `intern()` не используем как способ сравнения: он добавляет глобальное состояние и стоит дороже, чем `equals`. Правило не требует знать, что лежит в pool.
